# 简历精修工作台

入口：已生成草稿的职位 → 更多操作 → 编辑简历。

- 左侧为当前 JD 的本地硬门槛与关键词；中间沿用可保存的简历内容编辑器；右侧为选中经历要点的事实建议。
- 视口宽度大于 1100px 时为三栏；701–1100px 时岗位要求独占上行，内容编辑器和建议并列；不超过 700px 时按岗位要求、内容编辑器、建议顺序单栏堆叠，编辑弹窗占满视口。沿用 Aurora / Cosmic 主题，仅扩展 `.tailor-workspace` 及相关编辑弹窗样式，不修改全局视觉方向或 `DESIGN.md`。玻璃用于建议控制层，正文保持稳定阅读底面；系统请求减少透明效果时建议层改为不透明。
- `POST /api/resume/tailor-live` 需要本机 Action Token，只读，不调用云 API、不消耗模型额度、不更新 Profile。
- 建议只从本段绑定的已确认事实中生成：“保留依据”保留事实原文与顺序；“清晰表达”按 JD 相关度排序，并保守整理句首与行动/产出标点；“聚焦重点”选取最相关的一条完整事实。责任范围、数字与限定语不升级。三种策略可能得到相同文本，不是三种 AI 自由改写；缺少事实时不生成，跨经历混用、未知或未确认的事实 ID 不生成建议。
- “查看改动与依据”展示当前段落、确认事实、修改原因及 STAR 待补问题。缺口问题不是事实，不会自动写入简历；补充回答需另行核验入库。
- 点击经历要点后分析对应事实；编辑输入后等待 450ms 重新对照，旧建议会清除，过期响应不再应用。没有 JD 时仍可手动编辑和保存，但不能计算覆盖度。上述本地分析不使用云服务；编辑器保留的“从原简历导入（AI 解析）”是独立功能，不属于此无云分析承诺。
- 覆盖度是本地词表与当前编辑文本的重合，不是招聘系统 ATS 分数，也不是通过率。没有识别出关键词时显示“暂无”。
- 采用建议只修改当前尚未保存的草稿，支持撤销最近一次采用；若该段落又被手工修改，不自动撤销，以免覆盖新内容。保存、生成 PDF、人工审阅仍是独立步骤。手工文本不自动变成已确认事实。
- “预览排版”通过认证的 `POST /api/resume/preview` 在本机生成真实 PDF，返回页数并在中间显示，也可下载临时 PDF。不保存正式版本，不修改批准状态，不调用 Office 或云端；临时工作文件在请求结束释放。取消照片勾选会排除照片，非空客户端路径仅作为包含照片的意图，不能指定读取任意文件。
- 编辑、采用或撤销后旧预览失效；关闭工作台释放浏览器 Blob。预览是按按钮触发的真实排版，**不是边输入边自动分页**。它使用本地渲染器，若用户另行启用可选 Office 导出，正式 PDF 可能不同，因此保存后仍需审阅。本阶段不包含云端三种 STAR 自由改写或多赛道底稿库。

验证入口：`tests/test_resume_tailor_live.py`、`tests/test_resume_preview.py`、`tests/test_frontend.mjs`、`scripts/resume_tailor_qa.py`（合成档案；真实本地分析及 PDF 接口，模拟已保存草稿读取）。结果以实际运行记录为准。不证明真实招聘网站兼容性，也不表示桌面安装包已更新。
