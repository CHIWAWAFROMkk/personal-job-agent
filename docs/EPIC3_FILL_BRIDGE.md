# 双模式投递辅助与验证码后备

## 使用流程

1. 在扩展设置中填写本机工作台地址和配对密钥。只支持 localhost / 127.0.0.1，密钥不发送给招聘页面。
2. 在招聘页面打开插件，输入工作台岗位编号，先预览字段，再确认辅助填入。页面必须与岗位来源同主机，使用标准 HTTPS。
3. 需要短信验证码时，先选中网页中空的短信验证码输入框，再在插件点击接收此页验证码。
4. 回工作台打开该岗位的投递辅助，手工输入或点击粘贴，明确选择页面连接，再点击核对并录入。
5. 返回招聘页面检查结果，上传已审阅简历，手工处理登录、CAPTCHA、筛选问题和最终提交。

## 安全与兼容边界

- 只使用当前用户已确认资料；最小字段集不包含家庭地址、政治面貌、密钥或本地附件路径。
- 普通字段与验证码均采用静默写入，不派发 input/change 事件，也不点击提交。部分受控表单需要本人重新输入才能被网站识别；不能保证任意第三方页面没有自身副作用。
- 已有值、隐藏/只读字段、歧义标签、薪资/主观问题、文件上传与图形验证码不会自动填写。
- 验证码连接约两分钟有效，绑定标签页、完整 URL 和文档身份。页面跳转、关闭或失效后不自动转发到其他页面。
- 手动录入支持幂等请求；验证码只留内存、一次消费。入队不等于网页已填成功，网络断开时可能需要重新录入。
- 未选择页面连接时保留原有本机短信服务兼容行为；不会经扩展自动广播给招聘页面。
- 原有 browser-use / iPhone 短信同步仍独立存在。扩展不是绕过网站风控的工具。

- Python：`tests/test_fill_bridge.py`、`tests/test_sms_sync.py`。
- Node：`tests/test_extension_fill.mjs`、`tests/test_frontend.mjs`。
- 浏览器集成：`scripts/fill_bridge_qa.py` 使用真实本地接口和合成档案测试三个视口。
- DOM 安全回归：`scripts/extension_fill_qa.py` 使用真实浏览器 DOM、模拟扩展通信，检查不覆盖已有值、不触发提交和导航后停止。

- 源码更新不等于旧桌面 EXE 已更新；扩展也需要重新加载。未自动安装到用户浏览器。
