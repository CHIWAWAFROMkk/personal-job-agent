# Personal Job Agent 0.8.11 源码复核交接

本地候选版针对 0.8.10 独立复核留下的 R3-CLI / P2。此前 R1、R2 和界面连接测试的复核结果见 [0.8.10 源码交接](SECURITY_REVIEW_HANDOFF_0.8.10.md)。请分别核验源码包、桌面包和安装目录；只使用合成资料与模拟 SDK，不复制真实简历、密钥、岗位库或浏览器会话。

CLI `match --engine ai` 在用量预留内调用岗位匹配器。匹配器将 SDK 认证异常包装成不泄露密钥的 `OpenAIMatcherError`，并在 `__cause__` 中保留原异常。本版额度层仅对这个已知包装检查直接原因，再按原有服务商规则确认 `AuthenticationError` 与 HTTP 401；OpenAI 或 DeepSeek 官方地址明确拒绝时释放预留。不会根据错误文字、任意包装链或普通 4xx 释放；超时和 DeepSeek 自定义地址的结果不明请求仍保守占额。

建议先复跑审查方 `work/reproduce_cli_401.py`：两次模拟错误 Key 的 CLI 调用都应到达 SDK，`pending_requests=0`、`uncertain_requests=0`，第二次不应返回本机额度限制。再将第二次 SDK 响应改为合成成功结果，核对月限 1 下只记录一次成功。还应分别验证包装后的超时、只有“401”字样的错误以及自定义 DeepSeek 地址继续保留待核账预留。

本机用量仅是本地上限和请求历史，不等于服务商账单。实站 AI 自动代填仍暂停；材料准备和 `ready_to_apply` 不代表已经实际投递。浏览器上传哈希检查尚未接入可用生产路径，跨进程用户切换与进程中断时的跨文件绝对原子性仍不保证。Dream-RSI 只收录固定研究资料与评估，不执行外部实现。

本地源码验收：525 项 Python 测试、32 项前端测试通过。审查方原 CLI 合成复现重新运行，OpenAI 与 DeepSeek 各两次调用都到达模拟 SDK，未留下 pending 或 uncertain 预留。原脚本第二次仍模拟错误密钥，因此两次都返回认证失败；另有 CLI 测试将第二次改为成功响应，验证只结算一次成功。源码目录通过隐私扫描。

0.8.11 桌面包已构建，压缩包内 564 个文件通过隐私扫描。构建包和实际安装目录分别通过隔离数据下的启动、首页、岗位准备、复核对话框、版本冲突、伪造哈希及浏览器暂停状态验收；桌面快捷方式已切换到版本化安装目录，旧版安装目录和快捷方式备份保留。尚未重跑完整原生窗口验收，也没有连接真实 AI 服务商或招聘网站；这些结果不等于 0.8.11 已通过独立审查。
