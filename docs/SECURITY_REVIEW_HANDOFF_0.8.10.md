# Personal Job Agent 0.8.10 源码复核交接

这是针对 0.8.9 独立复核确认的三项 P2 的本地候选版；此前的产品边界见 [0.8.9 源码交接](SECURITY_REVIEW_HANDOFF_0.8.9.md)。源码、桌面压缩包和实际安装目录分别核验；测试通过不等于第三方安全认证。复核请只用合成资料和模拟服务商，不复制真实简历、密钥、岗位库或浏览器会话。

| 项目 | 本轮处理 | 建议独立复现 |
| --- | --- | --- |
| R1 云端事实待审 | 草稿保留独立的事实待审来源。本地改写、导入或再次渲染继承该来源；事实确认绑定当前内容和 PDF 摘要。旧版云端清单缺少确认记录时保守拒绝批准。 | 在云端草稿插入未有来源的获奖，调用本地“Agent 修改简历”，只勾 PDF 版面确认不得进入可投状态；逐项确认当前摘要后才可批准，再编辑应失效。 |
| R2 切换后的旧页面写入 | 成功切换用户时轮换工作台操作凭据与扩展 Profile 上下文。排队中的旧写入和切换后旧标签写入返回 HTTP 409，旧标签刷新后重新取得新上下文。 | 暂停切换并排队提交旧偏好；切换后核对新用户的目标岗位与城市没有被覆盖；再测试旧标签、扩展和当前标签。 |
| R3 401 额度恢复 | OpenAI SDK 或 DeepSeek 官方地址明确返回认证拒绝 401 时释放本机预留，可修正密钥重试。超时、DeepSeek 自定义地址及自定义兼容服务的结果不明请求继续占额待核账。 | 本机月限 1：模拟 401，随后模拟正确密钥成功，确认第二次到达 SDK 且只记录一次成功；超时仍不能免费重试。 |

升级时，0.8.9 的本地编辑草稿即使没有新来源标记，也会沿同岗位 `based_on` 版本链追溯云端草稿；前置清单缺失、越界、循环或跨岗位时保守阻断可投。旧清单缺少内容摘要的草稿需重新保存为新版，并重新检查 PDF 与事实，不能直接沿用旧批准。整份重新生成从已确认 Profile 建立新草稿，不继承旧草稿的自由文本。

导入和润色端点先返回未落盘的建议；正常工作台保存会传递来源标记，并从已有持久草稿继承。外部调用者若刻意删除一个从未保存过的建议标记，再将文字伪装为手工输入，服务端无法证明其云端来源；已保存草稿的后续修改不能借此清除来源。

浏览器扩展或其他使用 Agent Token 的客户端，写入前须先 `GET /api/agent/state` 取得 `profile_context`，随后每次写入携带 `X-Profile-Context`。同一个弹窗会话不要在写入前自动换取新上下文；收到 409 时应关闭旧弹窗或刷新页面，重新核对当前用户。工作台页面使用切换响应中的新操作凭据；其他标签需要重新加载。

实站 AI 自动代填仍暂停；“投递字段预览”只生成本机模拟计划。浏览器上传的哈希校验尚未接入可用生产路径，恢复实站代填前仍需单独审查和实站验收。已准备材料不代表已实际投递，本人仍需检查、上传并在招聘网站提交。

用量记录是本机上限与调用历史，并非服务商账单。跨进程用户切换及进程中断时跨文件绝对原子性仍未保证，切换备份需保留。同一 Windows 账户下恶意本机进程可以访问本地数据和服务；Profile 上下文防止误用旧页面，不构成对该进程的安全隔离。Dream-RSI 仅收录固定研究资料与评估，不执行第三方代码或自我修改。

本地验收：523 项 Python 测试与 32 项前端测试通过；隔离资料目录实际启动 0.8.10 打包程序，检查首页、岗位准备、简历审阅版本哈希、错误版本冲突和实站代填暂停。源码审查包与桌面发行包分别通过隐私扫描。此验收未模拟真实服务商扣费，也未操作真实招聘网站或最终投递。
