- Python 全套 **472 项通过**，Node 全套 **33 项通过**。新手流程脚本 12 个场景通过；高容量界面脚本覆盖 125 个岗位及失效深链、筛选边界。`git diff --check` 通过。
- Windows 成品的隔离启动与页面导航、简历准备和只读预览、版本冲突与错误哈希处理通过。源码审查包扫描 271 个文件、Windows 安装包扫描 834 个文件，均未检出已知个人资料或本机用户路径。
- 0.8.6 评审中的简历请求大小、AI 超时、同进程额度竞争、内存运行状态上限、配置错误吞没、切换服务丢失密钥、短信同步、桌面测试污染，以及大型首页快照路径已逐项处理或收紧。原报告部分行号和断言曾有误，复核以当前代码和实际运行结果为准。

## 我重点检查的边界

- `services/api_usage.py` 先为每个云端调用预留名额，成功后记录，失败时释放；文件损坏时阻止新调用，不把未知用量显示为零。相关 Web/CLI 入口均需按实际云端请求计数。
- `dashboard_routes/dashboard_api.py` 的连接测试只复用同服务、同地址已保存的密钥；不同地址不继承密钥。测试调用受当前及草稿中较严格的月度上限约束，未知 SDK 错误不原样回显。
- `dashboard_routes/jobs_api.py` 中付费面试准备需要 POST 与操作令牌；实验性的 browser-use 在设置了 AI 月度上限时仅允许模拟预览。通勤路线预留最多三次地图请求，并按成功返回次数结算。
- 大规模岗位快照使用批量数据库查询和单次材料索引；简历内容仍按岗位公司/名称与真实性校验选择，通过状态优先于修改时间的行为与原实现一致。首页不会把已阻止或超出通勤上限的岗位推荐为今日行动。
- 损坏的个人资料不会被空资料自动覆盖；页面会提示保留并备份原文件。不存在的岗位深链不会展示另一个岗位。日程输入拒绝夏令时不存在或重复的本地时刻，显式外地时区说明要求人工确认。

## 尚未解决或仍需实测

1. 本机额度预留仅保证同一进程内严格。桌面与命令行同时使用同一用量文件尚无跨进程事务；服务商真实余额仍以其控制台为准。
2. 同一 Windows 用户权限下的恶意本机程序仍可访问本地服务；页面 action token 主要防跨站网页，不能作为同用户进程隔离。
3. browser-use 的模型调用次数无法可靠逐次核算；未设本机上限时可运行，但用户需知晓其不进入本机成功请求计数。真实招聘站点、验证码、外部浏览器和最终提交链路未做端到端副作用验收。
4. 万级岗位的首次完整快照仍需数秒至十余秒，当前基准只用合成数据；短时缓存改善重复刷新，尚需长期真实数据验证。
5. `jobs_api.py`、前端 `main.js` 及 services 目录的结构仍偏大。当前先保持已验证的功能路径，后续应做有行为回归保护的分层重构。
