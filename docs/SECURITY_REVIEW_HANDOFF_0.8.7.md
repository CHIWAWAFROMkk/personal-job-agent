# Personal Job Agent 0.8.7 源码复核交接

这是 2026-09-23 的本地候选源码快照，尚未推送 GitHub，也未发布公开安装包。源码包不应包含真实简历、资料库、API Key、浏览器登录状态或构建缓存。请独立核验，不要把测试通过当作安全证明。

## 对 0.8.6 评审的处理

- H1：整份简历保存与润色路由现单独允许 128KB；普通 JSON 请求仍保留 16KB 限制。真实 HTTP 测试覆盖超过 16KB 的保存、读取、润色和超限拒绝。
- H2：原报告把完整简历生成误判为 15 秒通用客户端。实际路径是 `resume_compose` 调用 `resume_polish._invoke_ai`。现将完整生成设为 120 秒、普通润色与岗位匹配设为 45 秒、通用短任务设为 25 秒，并禁用这些调用的 SDK 自动重试。
- H3：`api_usage` 的单进程并发读写已加锁，包含并发回归测试。远程调用前的额度检查和调用本身尚未做原子预留；跨进程写入也不受该锁保护，因此本地月度上限仍是提示与尽力拦截，不能当严格付费限额。
- H4：审查发现 `dashboard.launch_assist_worker` 没有当前路由或界面调用点。现行“打开投递页”仅创建人工操作计划，不启动报告所述的 900 秒后台浏览器任务。轻量会话状态已设 100 条内存上限；重启后查询不到先前状态，但独立会话文件仍在数据目录。
- M1、M2、M11、L2、L6：启动配置失败可见；服务切换保留各自密钥，兼容 API 按地址隔离；请求体格式错误映射为 400；脚本 CSP 移除 `unsafe-inline`；支持列表补齐 DeepSeek。
- M7：报告标出的示例 Profile 实际位于 `desktop_window_test`，不是 `desktop_acceptance_test`。桌面窗口验收现只允许显式指定隔离临时目录，已有 Profile 时会拒绝运行，且在创建数据目录前检查。

## 请继续重点复核

1. 设置密钥分槽的迁移、清除与端点隔离；确认所有对外响应和日志都不回显密钥。
2. 并发调用的真实额度边界，以及 `resume_import.py`、`copilot_chat.py` 尚未统一的 SDK 超时与重试策略。
3. `/api/dashboard` 动作令牌的本机信任模型：跨站网页受 Host/Origin/Token 限制，同一用户下的恶意本机进程不在防护范围内。
4. 简历事实门槛、材料版本核对、岗位来源安全、扩展权限和本地 HTTP 请求边界。报告发现请附可复现的输入、调用路径和实际结果。
5. 数千岗位下的查询与导出性能，以及桌面长时间运行后的资源占用。现有隔离数据验收不能替代真实大规模测试。

真实招聘网站、真实账号和付费 AI 端到端调用尚未在此候选版执行；程序不得代用户提交申请、绕过验证码或把未确认事实写入简历。

本地候选版通过 451 项 Python 测试、30 项 Node 测试和源码隐私扫描；桌面打包验收需另行核对对应构建产物。
