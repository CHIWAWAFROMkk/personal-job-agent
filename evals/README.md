# 求职 Agent 固定评测 v1

复用仓库内手工构造的合成资料，不读取真实简历、数据库或个人配置。固定 15 个案例（其中有多组反例），直接调用业务代码；模型输出由 fixture 模拟，网络连接被禁止。

| 维度 | 案例数 | 验收内容 |
| --- | ---: | --- |
| 岗位匹配 | 6 | 已确认技能才算匹配；不满足、未知和可协商的硬条件；优先条件不误判为硬条件 |
| 简历真实性 | 4 | 引用正确经历；拦截未确认事实、虚构技能、夸大数字、无依据总结；允许同经历事实组合 |
| 来源核验规则 | 4 | 官方渠道识别、过期岗位、陈旧记录、缺少原始日期 |
| 隐私 | 1 | 审核报告不回显合成联系方式；提示不能编造数字 |

## 运行

在项目根目录使用 PowerShell：

```powershell
.venv/Scripts/python.exe evals/run_baseline.py
.venv/Scripts/python.exe evals/run_baseline.py --compare build/evals/<之前的报告>.json
```

报告保存在被 Git 忽略的 `build/evals/`，每次使用独立文件名。报告含逐项结果、失败堆栈、单项运行耗时、代码摘要、提交号、工作区是否有未提交改动以及 Python 版本。失败堆栈可能含本地路径，分享前先检查。

退出码 0 表示所有案例通过且对比有效；案例失败、跳过、基线不兼容或出现回退返回非零。对比报告列出通过转失败、失败转通过与耗时变化。测试输入文件变化后拒绝沿用旧基线，以免通过修改题目制造提升。

## 使用边界

- 这是离线规则和安全护栏基线，不是模型实际生成质量或真实岗位匹配准确率。来源测试不联网，不能证明岗位仍在招聘。
- 模型调用为 0、费用为 0；token 标记为未知/不适用。耗时仅为本地单次测试耗时，不是线上响应时延，也不设机器相关阈值。
- 当前只是执行评测，没有强化学习、模型训练或自动修改提示词。
- 每次优化先保留原报告，再用相同案例复测。失败时按案例 ID 和失败原因定位，不能为提分放宽真实性约束。
- 若接入真实模型，另建明确标记的评测模式，记录模型版本、提示词版本、实际用量、费用与多次运行结果；使用独立留出案例和人工核验，不能与本离线分数混合比较。
